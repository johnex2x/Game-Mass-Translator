# Game Mass Translator 使用手冊

本手冊以一般玩家／新手譯者為對象。第一次使用請先完成第 2 節的手動網頁翻譯流程；CLI、Agent、術語與 Player Package 是完成基本流程後再使用的進階功能。

## 1. 開始前須知

### 1.1 工具的工作方式

Game Mass Translator 會把遊戲文字和必要的來源快照整理成一個 `.rpytrans` 專案。你在專案裡翻譯與審核，最後才選擇把結果安裝到遊戲或輸出成 Player Package。

專案建立、編輯、預覽與診斷都是唯讀於遊戲來源的操作。只有你明確按下「安裝到遊戲」或輸出按鈕時，工具才會寫入你指定的目標。

### 1.2 先認識四個名詞

- **Entry／詞條**：一筆可翻譯的原文與譯文。
- **`.rpytrans` 專案**：本機 SQLite 使用者資料，保存來源快照、譯文、標記、語言方向與安裝狀態。請自行備份，不要把私人專案上傳到 Issue。
- **V／X／I**：V 是確定輸出、X 是需要重翻或重審、I 是刻意忽略。只有 V 會寫入遊戲或輸出。
- **Player Package／玩家包**：給其他玩家使用的翻譯成品資料夾，不包含遊戲本體。

### 1.3 送出文字前的隱私提醒

手動網頁翻譯時，你會自行把原文貼到選擇的網頁 AI；CLI／Agent 自動翻譯則會由選定的工具把文字送到其背後的服務商。請先確認遊戲內容的授權、服務條款與公司／作者的保密要求。完整網路行為見[隱私與網路說明](../PRIVACY.md)。

## 2. 從零完成第一次翻譯

以下步驟以「建立專案 → 手動批次翻譯 → 審核 → 安裝」為完整主線。示範畫面使用繁中介面；英文介面可由「工具 → 語言 / Language」切換。

### 步驟 1：啟動並建立專案

1. 從官方 ZIP 解壓縮後執行版本化的 EXE。
2. 按工具列的建立圖示，或開啟「工具 → 從遊戲建立專案…」。
3. 在「遊戲資料夾」按「瀏覽…」，選取遊戲根目錄，不要選到只包含某個存檔的子資料夾。
4. 確認視窗顯示的偵測類型，再按「開始」。工具會依根目錄內容選擇 Ren'Py、Unity、Translator++ `.trans` 或 MTool JSON 流程。

![從遊戲建立專案：選取遊戲資料夾並確認偵測類型](../assets/01-create-project.jpg)

如果資料夾根目錄同時有 Translator++ `.trans` 與 `ManualTransFile.json`，工具會先讓你選擇要匯入哪一種外部專案；外部專案會優先於引擎自動偵測。

### 步驟 2：確認專案與語言方向

建立完成後，工具會開啟 `.rpytrans`。先查看左側檔案樹、詞條總數與來源／目標語言。Unity 專案可能會列出多個語言證據；請確認方向後再使用 AI 批次。尚未確認方向的舊專案仍可瀏覽、手動編輯與匯出，但 AI 預覽、複製與批次功能會停用。

### 步驟 3：先看懂主表格

主表格的「原文」是遊戲快照，「譯文」是你準備寫回的內容。點選一列後，可在下方的「完整原文／完整譯文」窗格編輯；短文字也可以直接雙擊譯文格。Enter 保存、Esc 取消，點到別處會保存已改內容。

![主表格：檢查來源、譯文與目前的 V/X/I 狀態](../assets/02-project-review.jpg)

### 步驟 4：產生手動批次

1. 按工具列的「網頁批次翻譯」。
2. 設定「最大原文字數」。一個詞條不會被拆開；批次會依目前篩選範圍、狀態與左側檔案樹產生。
3. 第一次建議保留「附加提示詞」與「附加術語」。提示詞會告訴 AI 翻譯方向與格式規則；術語會帶入目前命中的對照。
4. 按「複製」，把左側完整批次貼到你選擇的網頁 AI（例如 Gemini）。

![網頁批次翻譯：複製左側原文批次，再貼回右側](../assets/03-web-batch.jpg)

對 AI 的要求很簡單但不能省略：輸出必須保留編號順序，一行原文對一行譯文，不要加入解釋、Markdown 標題或額外空行；`{tag}`、`[variable]`、`%s`、反斜線與 Ren'Py／RPG Maker 控制碼都要原樣保留。

### 步驟 5：貼回並分析

1. 在右側貼上 AI 的完整回覆，包括程式碼區塊也可以保留。
2. 按「分析結果並處理下一批」。工具會剝除外層程式碼區塊，檢查行數、編號與控制碼。
3. 檢查成功時，譯文會寫入專案但仍是「未確認」；行數或控制碼不符時，整批不會部分寫入，請修正回覆後重試。
4. 若 AI 同時回傳 `===術語===` 區塊，工具會先開啟術語審核；只有按「加入勾選項」才會保存新術語。

按「下一批」直到目前範圍完成。需要換批時可按「重新產生批次」；「復原上一批」只復原最近一次寫入的譯文，不會刪除已審核保存的術語。

### 步驟 6：複查並標記 V

貼回或手動保存的新譯文會回到「已翻譯、未確認」狀態。逐筆檢查語意、角色語氣、控制碼、變數與換行；確定能寫回遊戲的列按 **V**。需要重翻按 **X**，刻意保留原文按 **I**。

![V/X/I：綠色 V 才會輸出，橘色 X 需重翻，紅色 I 會忽略](../assets/04-review-marks.jpg)

可用 Shift 選取範圍、Ctrl 點選多列、Ctrl+A 選取目前篩選範圍的全部詞條。多選套用 V 會略過已標 I 的列；若要把單列 I 改成 V，請單獨選取該列。安裝前可把狀態篩選設為「未確認」或「X」，集中處理尚未審核的內容。

### 步驟 7：安裝並在遊戲中確認

1. 確認至少有一列 V，並保存專案。
2. 按「安裝到遊戲」。
3. 在安裝視窗選取正確遊戲資料夾，閱讀語言方向、目標檔案、檔案數與警告。
4. 只勾選你理解的選項；需要修改遊戲內建語言或 `*_Data` 的 Unity 路線時，工具會再要求明確同意。
5. 按「安裝到遊戲」後等待摘要顯示成功。若勾選「安裝完成後啟動遊戲」，工具會嘗試啟動遊戲；否則自行開啟並切換到目標語言。

![安裝到遊戲：確認目標資料夾、語言代碼與寫入選項](../assets/05-install-to-game.jpg)

基本成功條件是：安裝摘要成功、遊戲啟動後切到正確語言，且至少一條已標 V 的文字在遊戲中顯示為譯文。

## 3. 主畫面、編輯與標記

### 3.1 目前範圍

左側檔案樹、語境／原文／譯文篩選與狀態下拉會組成同一個「目前範圍」。表格清單、Ctrl+A、搜尋／取代與網頁批次都使用這份範圍；操作前先看頁碼列顯示的筆數與範圍，避免把整個專案誤套用。

### 3.2 編輯規則

- 原文欄是來源快照，不能直接改；需要修正來源時請重新建立或重新匯入專案。
- 完整譯文窗格支援右鍵複製、剪下與貼上；框選文字後可以加入術語。
- 內嵌換行與反斜線是資料的一部分。批次中的 `\n` 是可逆表示，貼回後工具會還原；不要自行合併或拆開詞條。
- 保存新譯文會清除 V／X，讓你重新複查；I 會保留，因為它代表刻意不輸出。

### 3.3 V/X/I 的實際效果

| 標記 | 意義 | 安裝／輸出 | 下一次批次 |
|---|---|---|---|
| V | 確定 | 寫入 | 跳過 |
| X | 需要重翻 | 不寫入 | 會再挑出 |
| I | 忽略 | 不寫入，遊戲保留原文 | 跳過 |
| 無標記但有譯文 | 已翻譯未確認 | 不寫入 | 等待審核 |

## 4. 三種翻譯方式

| 方式 | 適合誰 | 文字如何離開本機 | 主要優點 |
|---|---|---|---|
| 手動網頁批次 | 第一次使用、想逐批審核 | 由你複製到網頁 AI | 最容易理解，完全由你控制送出內容 |
| CLI 自動翻譯 | 已安裝並登入官方 CLI 的使用者 | 工具呼叫你選的 CLI | 自動重複批次、寫入與重試 |
| Agent 自動翻譯 | 使用 Claude Code／Codex CLI 等 coding agent 的使用者 | Agent 透過本機工作端點領取批次 | 可由 agent 續跑，但 GUI 仍掌握審核與安裝 |

三種方式共用同一套批次驗證、術語累積與「譯文先是未確認」規則；同一專案同時只能有一個未結束的自動工作。

### 4.1 CLI 自動翻譯（選用）

在網頁批次視窗按「CLI 自動翻譯…」。先重新偵測後端，選擇你已自行安裝並登入的官方 CLI（Claude Code、Codex CLI、Grok Build 或 Google Antigravity），再選目前範圍／整個專案、每批筆數、每批字數與重試次數。

![CLI 自動翻譯：確認後端、範圍、批次上限與重試次數](../assets/06-cli-automatic.jpg)

偵測只讀取版本，不會送出翻譯請求。開始前的告知會列出會送出的原文、提示詞與命中術語；不會送出完整 `.rpytrans` 資料庫。執行中專案會暫時唯讀，整批驗證失敗時不會部分寫入。網路錯誤、未登入或額度用盡會暫停，不會假裝跳過問題項目。工作可從 `.rpytrans` 續跑；自動產生的譯文仍要人工複查並標 V。

### 4.2 Agent 自動翻譯（選用）

第一次使用先在 Agent 視窗按「安裝 Agent Skill…」，閱讀並同意安裝到你使用的 coding agent。之後在網頁批次視窗按「Agent 自動翻譯…」，選取範圍、每批上限與重試次數，按「建立並等待 Agent」。

![Agent 自動翻譯：建立工作並等待外部 agent 領取批次](../assets/07-agent-automatic.jpg)

工具只在本機 loopback 端點提供待翻譯批次、驗證提交結果與顯示進度；agent 不能替你選遊戲、改範圍、標記 V 或安裝到遊戲。工作完成後仍須回到 GUI 審核所有譯文。停止工作會使未領取的 token 失效，但已完成且已驗證的譯文會保留。

## 5. 提示詞、術語與診斷

### 5.1 編輯提示詞

在網頁批次視窗按「編輯提示詞…」，可依目標語言查看可用變數、預覽渲染結果並保存專案提示詞。常用變數包括 `${source_language_name}`、`${source_language_code}`、`${target_language_name}`、`${target_language_code}`、`${target_style}` 與 `${engine_format_rules}`。

![編輯提示詞：查看變數、風格指令與固定格式規定](../assets/08-edit-prompt.jpg)

「儲存」只改目前專案；「設為我的預設」保存這台電腦的語言別預設。格式規定是解析批次所需的固定內容，不要刪除要求保留控制碼與一行對一行的部分。未知變數會阻止保存與批次產生。

### 5.2 術語與 Mismatch

按工具列「術語…」可以逐筆新增、編輯、刪除或匯入／匯出 UTF-8 TSV。術語內嵌在 `.rpytrans`，不會自動跨專案共用。你可以在完整原文／譯文窗格選取單行後右鍵「加入術語」。

![術語視窗：管理原文、譯名與 Mismatch](../assets/09-glossary.jpg)

「Mismatch」會找出原文含有術語、但譯文沒有指定譯名的列；它是審核提示，不會自動改譯文或阻擋安裝。修正譯文後重新分析，並把確認無誤的列標 V。

### 5.3 搜尋、取代與診斷

上方的語境／原文／譯文篩選可縮小目前範圍；「工具 → 翻譯診斷」會檢查格式、漏翻與涵蓋率。診斷是唯讀的，不會自動改譯文、標記或遊戲檔案。

## 6. 引擎分流與輸入準備

先用下表判斷路線；不確定時只選遊戲根目錄，讓工具顯示偵測結果，不要手動猜檔案。

| 來源 | 建立專案時選什麼 | 基本輸出／安裝 | 重要限制 |
|---|---|---|---|
| Ren'Py | 含 `game/`、`.rpa` 或 `.rpy` 的遊戲資料夾 | locale overlay、`.rpy`／`.rpa` 或 Player Package | 來源與 built-in baseline 變動時會要求處理衝突 |
| Unity／XUnity.AutoTranslator | 含 `<遊戲名>_Data` 的 Unity 遊戲 | XUAT 字典與設定檔 | `*_Data` 預設唯讀；缺 runtime 時需明確確認下載 |
| Unity／Naninovel | 通過 text map 結構驗證的 Unity IL2CPP x64 遊戲 | `*_Data/StreamingAssets/aa` 及必要 bridge | 只在結構確認後提供直接模式；首次啟動可能建立快取 |
| Unity Mono 靜態修補 | 工具顯示可驗證的 Mono 目標 | 受保護的目標資源檔 | 進階且會寫入 `*_Data`，需要明確確認與 pristine 備份 |
| Translator++ `.trans` | 遊戲資料夾根目錄的 `.trans` | 輸出新的 `_translated.trans` | 回寫遊戲由 Translator++ 完成；原 `.trans` 不變 |
| MTool JSON | 根目錄的 `ManualTransFile.json` | `<遊戲>_translated.json` | 只改 JSON 值；原始 JSON 不變 |

### 6.1 Ren'Py

工具可讀取 loose 或 RPA 來源，並保留不可變的 built-in baseline。安裝會建立語言 overlay，不會重打包原 RPA；如果你選擇替換既有 loose locale，工具會要求明確同意並先建立可驗證備份。重新匯入時若來源或 identifier 改變，請在衝突清單逐項保留、複製或 dismiss，未解決的衝突不會進入安裝。

### 6.2 Unity／XUnity.AutoTranslator

一般路線輸出 sidecar 字典與必要的 `AutoTranslatorConfig.ini` 變更，設定檔會留下 `.bak`。缺少 BepInEx／XUnity 時，只有在你確認後才會下載固定版本並驗證 SHA-256。中文缺字時依安裝摘要選擇 TTFLoader、MoeFont 或 yozai 路線；字型失敗不會抹掉已完成的字典安裝。

### 6.3 Naninovel 與 Unity Mono

Naninovel 直接模式會在 staging 驗證 bundle、catalog、bridge 與字型，成功後才寫入 `*_Data/StreamingAssets/aa`；首次 IL2CPP 啟動可能需要一至兩分鐘建立互通快取。Mono 靜態修補則從 `.gmt-pristine` 備份重建並逐項驗證，遇到非預期內容會中止。

### 6.4 Translator++ 與 MTool

RPG Maker 通常優先使用 Translator++ `.trans`，因為它能保留完整 `data/*.json` 欄位；若遊戲大量依賴執行期名字替換，才考慮 MTool。Translator++ 流程是：在 Translator++ 建立並保存 `.trans` → 用本工具翻譯 → 輸出 `_translated.trans` → 回到 Translator++ 的「Export Project」→「Export to Folder」寫回遊戲。MTool 流程是：建立專案 → 翻譯並標 V → 按工具列輸出 MTool JSON；兩者的來源檔都不會被本工具覆寫。

## 7. 安裝到自己的遊戲

安裝前先關閉遊戲，備份你自己的存檔與重要設定，並閱讀安裝摘要。只有 V 項目會輸出；藍色未確認、X 與 I 都會保留原文。

- Ren'Py 會寫入選定的語言 overlay；原 RPA 不會被重打包。
- 一般 Unity／XUAT 預設只寫根目錄 sidecar、設定與必要 runtime，不寫 `*_Data`。
- Naninovel 直接模式與 Mono 靜態修補會明確列出 `*_Data` 寫入，必須逐次確認。
- MTool 顯示「輸出 MTool JSON」而不是寫入遊戲；Translator++ 顯示輸出新 `.trans`，回寫由 Translator++ 完成。

安裝完成後先看成功摘要與備份位置，再啟動遊戲測試一段短文字。若遊戲更新導致 baseline／hash 不一致，請不要強行覆寫；重新建立專案通常比把翻譯套到不同版本安全。

## 8. 製作 Player Package

Player Package 是給其他玩家的輸出，不包含遊戲本體。先在自己的副本完成安裝與測試，再建立包：

1. 確認所有要分享的列都標 V，並在遊戲中測試。
2. Ren'Py 若要製作 `.rpa` 玩家包，先完成「安裝到遊戲」並啟動一次，讓 Ren'Py 編譯工具產生的 `.rpyc`。
3. 在安裝視窗的進階區按「製作 Ren'Py 玩家包」，或依 Unity 路線選擇完整 runtime 包／dictionary-only 包。
4. 將輸出資料夾與其中的授權、說明一併提供；若同名輸出已存在，工具會建立 `(2)`、`(3)` 等新資料夾，不會覆蓋舊包。

分享前請確認你有權散布翻譯與產生的支援檔，不要把遊戲本體、私人 `.rpytrans` 或工具 ZIP 放進包內。

## 9. 常見問題、隱私與安全

**Windows 顯示 Unknown Publisher？**  公開 EXE 未簽章。重新從官方 Release 下載並核對 ZIP SHA-256，不要停用安全功能。

**安裝後沒有翻譯？** 先確認詞條是 V、語言方向與引擎路線正確，再看安裝摘要、BepInEx／遊戲 log；若是 Unity，確認 runtime 與語言槽存在。

**AI 回覆行數不符？** 重新產生同一批，要求 AI 只輸出一行對一行的譯文；不要把多批回覆合在一起，也不要移除編號後的換行。

**字型顯示方塊？** 依 Unity 安裝摘要確認根目錄 TTF、loader／AssetBundle 與 7-Zip；字型流程失敗時可以先驗證字典安裝，再重新選另一條字型路線。

**遊戲更新後安裝被拒？** 這通常是 drift／baseline 不一致。保留原專案與備份，對新版本重新建立專案，再匯入可確認的舊譯文。

工具沒有遙測、帳號系統或自動更新。Unity runtime／字型下載只在你明確確認後進行並驗證雜湊；手動網頁、CLI 與 Agent 是否把原文送出，取決於你選擇的服務。公開回報請用 [GitHub Issues](https://github.com/johnex2x/Game-Mass-Translator/issues)，移除遊戲內容、私人路徑與機密；安全問題請走[私人安全回報](../SECURITY.md)。
